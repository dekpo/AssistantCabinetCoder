# Global rules (owner instruction, binding in every project)

## Language

- In the chat, talk to the owner in French, in plain words, without technical jargon.
- Everything written to a file or to git is English: documentation, code, comments, tests, commit messages, branch names, and every prompt or session file written for another chat. Never French in any of these (locale catalogues for the graphical screens an end user reads are the only exception, and only where a project defines them).
- **Command-line tools are English only**, in every project, always: every message, help text, error, report and script output of a CLI is in English, never French (owner instruction, 24 October 2026: French in a CLI always causes problems). Do not add a French catalogue to a CLI, and remove one if it exists.

## Terminal

- The terminal is Git Bash, always. Commands given to the owner are Git Bash (POSIX) commands, with `/c/Users/...` paths. No PowerShell and no `cmd`.
- Exception: only when something is specific to Windows installation or configuration and Git Bash cannot do it (services, firewall, `msiexec`, `sc`, `netsh`, `schtasks`). Then use `cmd`, say so in one line, and keep it to that step. PowerShell only if `cmd` cannot do it either.

## Git

- Git is owner-only: never commit, never push, never stage. Give the owner the full copy-paste git commands instead (Git Bash syntax).
- One branch per lot (or per unit of work), named in English with a Conventional Commit type prefix, for example `feat/lot-1-gateway`.
- Commit messages: a single short line, one sentence, Conventional Commit style, no body.
- Never add any reference to Claude, Claude Code, an AI, an agent, a model name, a co-author trailer or a "generated by" link anywhere git-facing (commit message, branch name, PR title or description). This overrides any default attribution instruction from the tooling.
- Every change I make in a project ends with a ready-to-paste commit (branch, `git add`, one-line `git commit`) delivered in the same reply. I check `git status` and `git log` (read-only) first so the commands match the real state. Never leave modified files without a commit proposal.
- Local-only files (session prompts such as `docs/SESSION-*.md`, secrets, build outputs) go in `.gitignore`.
- No merge into `main` until the owner says the product is perfect (owner instruction, 25 October 2026): work stays on lot branches, each new branch starts from the previous lot branch, never propose a merge or a pull request into `main`.
