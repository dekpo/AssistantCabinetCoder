## Why this lot exists

Written from the server project's prompt of 21 November 2026 (server decision D-095), checked against this repository the same day. The owner accepted the lot on 21 November 2026 and answered yes to three questions: (1) the lot starts with Part A, measures, then stops; (2) the window-overflow sentence shows the server's numbers, which needs small changes to `src/client.ts` and `src/codes.ts`; (3) if no error type stops the editor's retries, the agent may propose plan B (below).

Facts checked on 21 November 2026:

- **Every refusal reaches the editor as a plain `Error`** (`src/provider.ts`, `chat`, the `failure` built from `describeCode`). On VS Code 1.147.0 the editor's agent harness retried a `context_too_large` refusal five times, about 15 seconds, and framed the sentence with "Failed to get response from the AI model; retried 5 times ... Last error: 502" (lesson 19). Read in the installed 1.147.0, not measured: the retry message lives in the native runtime of the bundled Copilot SDK (`runtime.node`), next to "exceeded maximum number of retries" and "rate-limited requests"; the Copilot extension's bundle has an advanced setting `chat.advanced.retryServerErrorStatusCodes` whose default is `"500,502"`. Which thrown value stops the retries is **not** readable there: it is measured (lesson 17).
- On a server dedicated to coding a retried failure can cost a lot: a `provider_error` 504 after `IDE_REQUEST_TIMEOUT_SECONDS` (900 s by default) retried five times is up to 90 minutes, holding the editor door's single generation slot (`IDE_MAX_CONCURRENT_GENERATIONS=1`).
- **The server's numbers are dropped**: `failureFromResponse` (`src/client.ts`) keeps the code and the status only; a `context_too_large` envelope carries `data.estimated_tokens` and `data.context_window` (the guard) or `data.chars` and `data.limit` (the character ceiling). The sentence today is "The conversation is too long for this model. Start a new chat or attach less." The server's estimate counts 2 characters per token, about 2.3 times the real count for the editor's Agent request (about 50 500 estimated against 21 597 real on `devstral-2`, D-024), so the sentence calls it an estimate of the server, never a count.
- **The cancellation is wired** (`toSignal` in `src/extension.ts` aborts the request when the editor's token fires), but in Ask on 1.147.0 the editor never fired it (lesson 13). Agent, Plan and the second turn of a chat were never measured.
- **The Mac's server on 21 November 2026** (read-only `GET /ide/v1/models` and `GET /health`): `/health` reports version **0.1.13** (the server's handoff says 0.1.11, then 0.1.12 from server Lot 39: the owner asked the server project which is right); 23 aliases, among them `devstral-2` (65536, 16384, tools, no vision), `gpt-oss:120b` (131072, 16384, tools, no vision), `gpt-oss:20b` (32768, 16384, tools, no vision), `qwen2.5-coder:14b` and `qwen2.5-coder:7b` (32768, 16384, tools, no vision); features `agents` true, `document_analysis` false, `image_description` false.

## Part A: measure, then stop (agent and owner)

May change in Part A: `test/stub-gateway/stub.ts` and `test/stub-gateway/run.ts` (additions only, kept for Part B), this file. **A temporary probe** in `src/extension.ts` (marked `PROBE X1e`, never committed, removed before Part B and checked with `git diff feat/x1d-agent-budget -- src/extension.ts`, which must be empty).

1. **Baseline**: the whole suite (263 tests passed on 21 November 2026, before any edit).
2. **The stub learns refusals** (additions only): a scenario `refuse`, chosen with the marker `[stub:refuse:<code>]`, answers the contract's envelope of that code with its status (`context_too_large` 413 with `estimated_tokens` and `context_window`, `payload_too_large` 413, `model_not_permitted` and `model_alias_not_allowed` and `provider_capability_unsupported` 400, `invalid_request` 422, `empty_answer` 502, `provider_error` 504, `server_busy` and `provider_unreachable` 503, `rate_limited` 429). `npm run stub` prints one line per chat request to its own console: a sequence number, the scenario, the code, the model and the count of tools (counts and names of the stub's own scenarios only, never text).
3. **The probe** (temporary): `provideLanguageModelChatResponse` rethrows the provider's failure as one of eight kinds, chosen by the code of the refusal, so that one chat can try them all: a plain `Error` (`context_too_large`, today's behaviour), `vscode.LanguageModelError.NoPermissions` (`payload_too_large`), `.Blocked` (`model_not_permitted`), `.NotFound` (`model_alias_not_allowed`), an `Error` carrying a `code` property (`invalid_request`), an `Error` carrying a `cause` (`provider_capability_unsupported`), an `Error` carrying `status` 400 (`empty_answer`), `vscode.CancellationError` (`rate_limited`). The message stays the sentence of `messages.ts`.
4. **The owner's clicks** (a throw-away profile, as in X1d): in Agent, one prompt per kind; the stub's console counts the requests of each prompt (1 = not retried, 6 = retried five times) and the owner writes what the chat showed. Then Ask and Plan for the plain `Error` and for the kinds that were not retried. Then **the stop button**: the scenario `long` (about a minute of text), Stop after a few words, in Agent and in Plan, on the first and on the second turn of a chat; judged on the extension's log line (its duration and `code=cancelled`), never on the screen (lesson 13).
5. **Stop and report to the owner in French**: the table of what was retried, the mapping proposed for the contract's codes ("cannot succeed by retrying": `context_too_large`, `payload_too_large`, `unauthorized`, `model_alias_not_allowed`, `model_not_permitted`, `provider_capability_unsupported`, `invalid_request`, a 504 timeout and the extension's own `timeout`; "may succeed later": `server_busy`, `provider_unreachable`, `rate_limited`), what the stop button did, and the options with their cost. **Plan B**, if no kind stops the retries: the extension remembers in memory only, for about a minute, a fingerprint of a request the server has just refused and answers an identical request at once with the same sentence, without calling the server (no fingerprint, text or count of it is ever written). The owner chooses; nothing of Part B starts before the answer. Anything the server should know is written as a message ready to paste in the server's chat.
