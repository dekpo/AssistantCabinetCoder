## Build

**Manifest.** `name: assistant-cabinet-coder`, `displayName: Assistant Cabinet Coder`, `publisher` (the owner's answer recorded in `docs/DECISIONS.md`), `version: 0.1.0`, `engines.vscode`: `^1.140.0`, kept as set by D-007 (the spike measured 1.143.1 only; a lower minimum is untested and would change the pinned `@types/vscode`, which needs the owner), `categories: ["AI", "Chat"]`, `extensionKind: ["ui"]` as in the spike (remote windows are untested, the README says so), `capabilities.untrustedWorkspaces.supported: "limited"` (VS Code disables the whole chat and the extension's models in Restricted Mode anyway; "limited" only keeps the commands usable), activation only when needed (never `*`; commands activate it, the provider's event is added by Lot X1b). Commands (category `Assistant Cabinet Coder`): `assistantCabinetCoder.manage` (a quick pick: Set API Key, Clear API Key, Select CA File, Test Connection, Show Output), `setKey`, `clearKey`, `selectCaFile`, `testConnection`, `showOutput`.

**Settings**, all `"scope": "machine"` (a repository's `.vscode/settings.json` must never be able to point the key at another host; the spike's (g) proved it): `assistantCabinetCoder.serverUrl` (empty), `.caFile` (empty), `.autoDiscover` (`true`), `.requestTimeoutSeconds` (900: the limit with no byte received, per request).

**`src/platform.ts`.** The only module that names operating-system folders (the seam for a second platform: an added branch, never a rewrite). Given the platform and the environment as arguments (so every layout is tested on any machine): Windows `%ProgramData%\AssistantCabinetServer\config`; macOS `/Library/Application Support/AssistantCabinetServer/config`; any other platform: no folder (the user sets `serverUrl`). Both layouts were checked against the server's `paths.py` on 27 October 2026; the README says macOS is untested until a Mac is available.

**`src/discovery.ts`** (pure). `serverUrl` when set. Else, with `autoDiscover` and an installation on this machine, read **only** its `server.env` (since the server's Lot 10 the `config` folder is readable by ordinary accounts and `server.env` holds no secret). Take `SERVER_BIND_ADDRESS`, `SERVER_PORT`, `TLS_MODE`, `TLS_SUBJECT_ALT_NAMES`, `AUTH_MODE`. URL: `http(s)://<host>:<port>` where `<host>` is the bind address, or, when it is `0.0.0.0` or `::`, `127.0.0.1` for plain HTTP and the first `TLS_SUBJECT_ALT_NAMES` entry for HTTPS (the certificate is valid only for those names). The authority file defaults to `ca.pem` in the same folder when `caFile` is empty (a public copy kept since MSI 0.1.11; older installs have none: the message says so). Parse `KEY=VALUE` the way the server does (no quotes, `#` comments, last word wins, unknown keys ignored); never write, execute or forward anything. Nothing else is read from disk: never the secrets folder, never the workspace. If nothing is found, the messages say what to set. Tested with strings.

**`src/transport.ts`.** `node:http` / `node:https` only. For `https:` pass `ca` read from the authority file at each request (an unreadable file, a file that is not a certificate, or a file that contains a private key is refused with a clear message); never `rejectUnauthorized: false`. `Authorization: Bearer <key>` from the secret store only, and only when a key is set. Abort when no byte arrives for `requestTimeoutSeconds` and on the cancellation token. One keep-alive agent per server URL (bounded). Redirects are not followed. JSON response bodies are size-capped (the stream is not). Streaming and non-streaming calls share one code path for connection, headers and errors.

**`src/sse.ts`** (pure). Incremental SSE parser: lines split across chunk boundaries, `: comment` lines ignored, `data: [DONE]` ends, a `data: {"error":...}` event surfaces as a typed error, invalid JSON is a typed error that never contains the payload.

**`src/client.ts`.** Typed calls over the transport: `GET /health`, `GET /ide/v1/models` (reads `ide_api`, `features`, `data[]`; refuses a body whose `ide_api` is not `1` with the machine code `ide_api_mismatch`; tolerates unknown fields and a missing `features`), and the machine-code mapping of every status and error envelope of contract section 3 ("Errors") plus `404` -> `ide_surface_off`, `401` -> `key_needed`, no connection -> `unreachable`, untrusted certificate -> `certificate_untrusted`. Machine codes cross module boundaries, never sentences. The chat call itself is Lot X1b's.

**`src/messages.ts`.** Every user-facing sentence, one English sentence per machine code, no URL literal except documentation links; the exact administrator instruction for `ide_surface_off`: "The server has not turned on the editor surface. Ask the administrator to run: cabinet-server config set IDE_ENABLED=on, then cabinet-server restart."

**`src/keys.ts` and commands.** `setKey`: input box with `password: true`, stored in the secret store under a fixed name per server URL; `clearKey`; `selectCaFile` (writes the machine-scoped `caFile` setting only); `testConnection`: `GET /health` (reachable or not), then `GET /ide/v1/models`, showing per model the window, output ceiling, tools, vision, and the `features` the server offers, or the machine code in plain words. For a model that does not report tool calling it adds that VS Code 1.143.1 does not offer it in the chat picker in any mode (measured by the spike). An empty-state message for each failure: off, key needed, unreachable, certificate untrusted, version mismatch (what exactly to do).

**`src/log.ts` and the status bar.** The **output channel**: one line per call (time, alias when known, status, duration, token counts when known, tool-call count, machine code), built from a closed list of allowed fields, never text. A status bar item (right side, small) shows `Cabinet: connected | off | key needed | unreachable` and opens `manage` when clicked; it hides when the extension is not configured and nothing was found.

**`src/extension.ts`.** The thin VS Code adapter only (registration, secret storage, commands, status bar): everything it calls is tested elsewhere.

## Tests (no VS Code needed, except the thin adapter, which the owner walks)

- **Stub gateway** `test/stub-gateway/` (plain `node:http`, also `npm run stub` for demos): `GET /health`, `GET /ide/v1/models` with three models (one with tools and vision, one with tools only, one with neither), `POST /ide/v1/chat/completions` with a scripted text stream, a scripted tool call, a scripted error, a slow first byte, a split SSE; modes: `ide_api: 2`, `404`, `401`, a body above the size cap. Later lots extend it additively (agents, files analysis).
- Discovery (specific bind address, `0.0.0.0` plain and HTTPS with names, missing file, garbage file, last word wins, comments, macOS and Windows path strings, an unsupported platform); platform paths; SSE parsing cases; every contract error code mapped to its machine code and message; `ide_api` mismatch; `404`/`401` handling.
- Transport: cancellation aborts the socket; first-byte timeout; keep-alive agents bounded; HTTPS against a stub with a throw-away authority created in the test (trusts the authority file, refuses another, refuses a file with a private key, re-reads the file at each request); no redirect followed.
- The manifest (every setting `machine`, ids match the identifiers table, no `*` activation, no runtime `dependencies`).
- **Guard tests:** language guard (no French diacritics in tracked sources, tests and docs outside one named fixture file); **no-leak** (a unique secret placed in a message, a tool argument, a tool result, an image payload, a file name and the key never reaches the output channel lines, thrown error messages or any file); **no-network and no-risk** (the sources contain no URL literal other than documentation links in `messages.ts`, no import of an HTTP client or telemetry package, and none of `child_process`, `eval`, `new Function`, `vm`); **drift** (the README mentions every command and setting of `package.json`); **contract** (`docs/IDE-CONTRACT.md` equals the server's `docs/IDE-CONTRACT.md` when `../AssistantCabinetServer/docs/IDE-CONTRACT.md` exists, otherwise the test is skipped with a reason).
