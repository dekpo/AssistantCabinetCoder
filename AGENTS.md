# Rules for any agent working in this repository

Short form of the binding rules. The practices are in `docs/VIBE-CODING-PRACTICES.md` (read it first, it is not repeated here). Then read `docs/DECISIONS.md`, `docs/LESSONS.md` (all of it), `docs/ARCHITECTURE.md`, `docs/HUMAN-TESTS-PROTOCOL.md` and `docs/SPIKE-FINDINGS.md` (the facts measured by Lot X0 override any assumption about VS Code).

## Language

- Every file is English: code, comments, tests, documents, commit subjects, machine codes, prompts written for another chat. No French anywhere.
- User-facing messages of the extension are English and live in one file, `src/messages.ts`. Command-line scripts speak English only.
- The agent talks to the owner in French, in plain words, without jargon.

## Git

- Git is owner-only: never commit, stage, push or tag. Read-only `git status`, `git log`, `git diff` are fine.
- At the end of a lot give the branch name, a one-line Conventional Commit subject and the full copy-paste Git Bash commands, written after reading `git status` and `git log`.
- One branch per lot, created from the previous lot's branch, never from `main`. Nothing is proposed for `main`, no pull request.
- No AI attribution anywhere git-facing: no model name, co-author trailer or "generated by" link in a commit, a branch name or a PR.
- Local-only files (session prompts in `docs/SESSION/`, secrets, build output) stay in `.gitignore`.

## Privacy

- No telemetry. No network call to any host other than the configured server.
- No code, message, file content, image, file name, tool argument or tool result is written anywhere (file, output channel, error message). Logs carry codes, durations and counts only.
- The API key lives only in VS Code's secret storage and is never printed or logged.
- The extension never changes a setting that is not its own and never disables another extension. Privacy rules are tests, not intentions.

## Terminal

- Commands written for the owner are Git Bash (POSIX) commands with `/c/Users/...` paths. No PowerShell, no `cmd`, except a step specific to Windows that Git Bash cannot do (say so in one line).

## Tests and quality

- Zero runtime dependencies (only `node:` built-ins). Dev dependencies pinned to exact versions, lockfile committed, no install script (`.npmrc` sets `ignore-scripts=true`). Free licences only. Ask the owner before adding a dependency.
- Tests run on the compiled output with Node's built-in runner (`npm test`). Every behaviour is covered by a test that needs neither VS Code nor the network.
- Run the targeted test while working; the full suite, `npm run lint` and `npm run format` once at the end.
- An existing test is never edited to make it pass: stop and tell the owner.
- Never claim what was not shown: the agent cannot see the owner's screen, so every editor step is the owner's.

## What never to touch

- `docs/IDE-CONTRACT.md` (vendored from the server project; a change is made there and copied over) and `docs/VIBE-CODING-PRACTICES.md`, unless the owner asks.
- Files outside the list a lot names. The server projects `AssistantCabinetServer` and `AssistantCabinetAI` are never changed from here.
