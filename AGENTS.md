# Rules for any agent working in this repository

Short form of the binding rules. The practices are in `docs/VIBE-CODING-PRACTICES.md` (read it first, it is not repeated here). Then read `docs/DECISIONS.md`, `docs/LESSONS.md` (all of it), `docs/ARCHITECTURE.md`, `docs/HUMAN-TESTS-PROTOCOL.md` and `docs/SPIKE-FINDINGS.md` (the facts measured by Lot X0 override any assumption about VS Code).

## Language

- Every file is English: code, comments, tests, documents, commit subjects, machine codes, prompts written for another chat. No French anywhere.
- User-facing messages of the extension are English and live in one file, `src/messages.ts`. Command-line scripts speak English only.
- The agent talks to the owner in French, in plain words, without jargon.

## Git

- Git is owner-only: never commit, stage, push, merge or tag, and never offer to. Read-only `git status`, `git log`, `git diff` are fine. The agent **always** gives the commands and the owner runs them.
- At the end of a lot give the branch name, one-line Conventional Commit subjects and the full copy-paste commands (Terminal, zsh), written after reading `git status` and `git log`.
- Branches (owner, 23 November 2026, D-033): `main` holds what is tested and validated as a release; `develop` gathers the validated lots between releases. Each lot has its own branch `feat/<lot>`, created from `develop`; once its human test passed and the owner validated it, it is merged into `develop` (`git merge --no-ff`). When the owner judges a version good enough, `develop` is merged into `main`. No pull request.
- No AI attribution anywhere git-facing: no model name, co-author trailer or "generated by" link in a commit, a branch name or a PR.
- Local-only files (secrets, build output) stay in `.gitignore`. The session prompts in `docs/SESSION/` are tracked (decision D-021).

## Privacy

- No telemetry. No network call to any host other than the configured server.
- The chat panel's conversations are saved on the user's machine, in the extension's private storage for the workspace, by `src/store.ts` alone (decision D-027: this is a professional coding tool and conversations must survive a reload; the desktop application's privacy defaults do not apply here). Nothing else of them is written: no code, message, file content, image, file name, tool argument or tool result reaches the output channel, a log line or an error message. Logs carry codes, durations and counts only.
- The API key lives only in VS Code's secret storage and is never printed or logged.
- The extension never changes a setting that is not its own and never disables another extension. Privacy rules are tests, not intentions.

## Terminal

- Commands written for the owner are POSIX shell commands: on macOS they run in Terminal (zsh) with `/Users/...` paths; on Windows they stay Git Bash with `/c/Users/...` paths. No PowerShell, no `cmd`, except a Windows-only step that Git Bash cannot do (say so in one line).

## Tests and quality

- Zero runtime dependencies (only `node:` built-ins). Dev dependencies pinned to exact versions, lockfile committed, no install script (`.npmrc` sets `ignore-scripts=true`). Free licences only. Ask the owner before adding a dependency.
- Tests run on the compiled output with Node's built-in runner (`npm test`). Every behaviour is covered by a test that needs neither VS Code nor the network.
- Run the targeted test while working; the full suite, `npm run lint` and `npm run format` once at the end.
- An existing test is never edited to make it pass: stop and tell the owner.
- Never claim what was not shown: the agent cannot see the owner's screen, so every editor step is the owner's.
- Human tests (owner, 23 November 2026): no step needs an action faster than about 20 seconds (a stop scenario leaves 20 to 30 seconds of window), and the owner is never asked what they saw or felt during a few seconds. The agent checks that itself (stub console, log, files, the screenshots already sent) and asks only for unhurried clicks, texts to paste (given ready to copy) and named screenshots.

## Sessions

- Every session starts from a prompt file prepared in advance from the implementation plan (`docs/SESSION/SESSION-<lot>.md`), launched by the owner in a **new chat tab**, so that each session leaves its own trace. One chat never runs across lots: at the end of a lot the agent writes the handoff (run record, decisions, lessons) and aligns the next prompt file before stopping, and says which file to launch.

## What never to touch

- `docs/IDE-CONTRACT.md` (vendored from the server project; a change is made there and copied over) and `docs/VIBE-CODING-PRACTICES.md`, unless the owner asks.
- Files outside the list a lot names. The server projects `AssistantCabinetServer` and `AssistantCabinetAI` are never changed from here.
